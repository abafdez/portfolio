# Portfolio — project guide for Claude

Alfonso's personal portfolio, built as a **learning project** (Alfonso is a junior dev).

## How we work

- **Faster learning mode (since Phase 3).** Claude may write the code for each step, then explains the concepts behind it, with doc links.
- **Before moving to the next step, Claude interviews Alfonso** with 2–4 short questions on that step's concepts (the why, not trivia). If an answer is off, clarify and re-check before moving on.
- Keep the code small and in the project's style so Alfonso can read all of it. Point out anything worth trying by hand (small experiments in DevTools or the build output).
- One branch and one PR per phase. Write **one Bitácora entry per topic** (not one per phase), and copy each one to the Obsidian vault project `10 Projects/Portfolio/` (use the `obsidian-obsidianai` skill).
- Write **one draft blog article per topic** too (e.g. design tokens, cascade layers, dark mode), in `content/blog/drafts/<slug>/<slug>.md`. Drafts only exist in dev; publishing a post means moving its folder to `content/blog/published/` (Alfonso's call).
- The learning path (phases 0–11; 9.5, components in markdown, is next after `feat/post-folders`; 10, English + Spanish, and 11, a CMS, are planned for later) is in [learning-path.md](learning-path.md). Check which phase is current before suggesting work.

## Folders

- `content/` — markdown sources, published from Phase 6 on:
  - **Every post and entry is a folder named like its file, with its images next to it** (`<slug>/<slug>.md`, `<slug>/diagram.png`); `slugOf()` in `content.ts` fails the build if the names differ. Write images as plain `![alt](./diagram.png)`: the `markdown()` plugin in `vite.config.ts` turns each into an import + `<enhanced:img>` (AVIF/WebP, width/height), and the build fails on a missing file, an empty alt, or a double quote in an alt or caption (mdsvex 0.12 doesn't escape it, and the page was a bare 500). Commit images at about 2× display width (~1600 px), compressed, and check screenshots for personal data (the CV stays private). When copying an entry with images to the vault, copy them to `_attachments/` and link them as `![[file.png]]`. `![alt](./x.png "Caption")` becomes a `<figure>` (`src/lib/enhance-media.ts`, unit-tested; mdsvex splits long tags over lines, hence `\s+`); post images are `loading="lazy"`. **Videos** are HTML in the markdown (`<video>`, `<source>`, `<track>`, `poster`): every `./` `src`/`poster` becomes a plain import (hashed URL, file used as is, nothing re-encoded), and a `<video>` without `width` and `height` fails the build. Animated GIFs aren't animated (enhanced-img keeps the first frame), so recordings are MP4 (+ optional WebM first), no autoplay, `muted`; the publishing guide has the ffmpeg commands. **Headings in markdown** get ids (`rehype-slug`) and link to themselves (`rehype-autolink-headings`, `behavior: 'wrap'`, so the heading's accessible name doesn't change; a CSS `#` on hover/focus in `.prose`); a cast in `vite.config.ts` because mdsvex 0.12 types unified v9; a broken `#link` fails the build (`prerender_missing_id`, tested). **Covers**: `cover.{avif,png,jpg,webp}` (AVIF exported at quality ≥ 70) in a content folder, 16:9, ≥ 1600 × 900, **what matters in the middle** (cards crop a square from the middle), alt text as `cover:` in the frontmatter (`checkCover()` fails the build if one is missing). `src/lib/covers.ts` globs `/content/**/cover.*` (drafts only in dev) and finds a cover by folder: `coverOf(entry.folder)` (`Entry.folder` in content.ts) gives `{ picture (16:9, w 1600;800;480), square (aspect 1:1, w 480;240, cropped at build), preview (1200px JPEG for og:image) }`. Only blog posts use them so far; **Alfonso plans covers for Bitácora entries, Awesome lists, projects and the section pages** (a section cover could be `content/<section>/cover.png`, found by folder too; projects' covers would need their own glob in `src/lib/projects/`). Card thumbnail: square beside the text (12rem, centred), 16:9 on top below 34rem of card width; both `alt=""` and lazy, so only the shown one downloads. Post hero: `fetchpriority="high"`; og:image + `summary_large_image`. Without a cover, a CSS tile (blueprint grid + first tag; square beside, a 4:1 strip on top). `checkUniqueSlugs()` fails if a slug is in both `drafts/` and `published/`.
  - **HTML tags in prose always go in backticks** (`` `<details>` ``, `` `<profile>` ``; Alfonso, 2026-11-07). mdsvex passes HTML through as it is: a made-up tag becomes an element that never closes (`element_implicitly_closed`), and a real one like `<aside>` silently becomes markup. **A bare tag in a `.md` file fails the build** (`element_implicitly_closed` only, Alfonso's call; `onwarn` in `vite.config.ts`, forwarded by `sveltekit()` to vite-plugin-svelte; names the tag; no line number, since Svelte counts mdsvex's output lines, so it prints the frame); every other warning is printed as usual.
